# OpenCode 整体架构

## 目录结构概览

OpenCode 的源代码位于 `src/` 目录下，包含32个主要子目录：

```
src/
├── index.ts              # 入口点，CLI 命令注册
├── acp/                  # Agent Client Protocol（IDE 集成）
├── agent/                # 代理（Agent）配置与管理
├── auth/                 # 认证管理（API Key、OAuth）
├── bun/                  # Bun 运行时特定代码
├── bus/                  # 事件总线（发布订阅）
├── cli/                  # CLI 命令定义
├── command/              # 命令系统
├── config/               # 配置管理（七层优先级）
├── env/                  # 环境变量处理
├── file/                 # 文件操作
├── flag/                 # 命令行标志/特性开关
├── format/               # 代码格式化
├── global/               # 全局路径常量
├── id/                   # 唯一标识符生成
├── ide/                  # IDE 集成
├── installation/         # 安装信息
├── lsp/                  # LSP（Language Server Protocol）集成
├── mcp/                  # MCP（Model Context Protocol）集成
├── patch/                # 补丁处理
├── permission/           # 权限系统
├── plugin/               # 插件系统
├── project/              # 项目上下文与实例管理
├── pty/                  # 伪终端
├── provider/             # AI 提供商抽象
├── question/             # 用户交互式问题
├── scheduler/            # 调度器
├── server/               # HTTP 服务器
├── session/              # 会话管理（核心）
├── share/                # 会话分享
├── shell/                # Shell 集成
├── skill/                # 技能（Skills）系统
├── snapshot/             # 文件快照
├── storage/              # 存储抽象层
├── tool/                 # 工具系统
├── util/                 # 工具函数
└── worktree/             # Git 工作树
```

## 核心设计模式

### 1. 命名空间模式（Namespace Pattern）

OpenCode 广泛使用命名空间模式来组织相关功能。大多数模块导出一个命名空间对象，包含相关的函数和类型。

**示例：** `src/session/index.ts`

```typescript
export namespace Session {
  // 命名空间内的函数
  export const create = fn(...)
  export const get = fn(...)
  export const update = fn(...)

  // 命名空间内的类型
  export const Info = z.object({...})
  export type Info = z.infer<typeof Info>
}
```

**优点：**
- 相关功能聚合在一起
- 避免全局命名污染
- 清晰的模块边界

### 2. 实例作用域状态（Instance-Scoped State）

`src/project/instance.ts` 提供了异步上下文管理器，实现每个目录的独立状态。

**核心概念：**

```typescript
await Instance.provide({
  directory: "/path/to/project",
  init: InstanceBootstrap,
  async fn() {
    // 在这个回调内，可以访问 Instance.project、Instance.worktree 等
    // 每个目录有独立的项目状态
  }
})
```

**用途：**
- 支持同时处理多个项目
- 每个项目独立的配置、存储、会话
- 请求级别的上下文隔离

### 3. 事件驱动架构（Event-Driven Architecture）

`src/bus/` 实现了类型安全的发布订阅事件系统。

**事件定义：**

```typescript
export const Event = {
  Created: BusEvent.define(
    "session.created",
    z.object({
      info: Session.Info,
    }),
  ),
  Updated: BusEvent.define(
    "session.updated",
    z.object({
      info: Session.Info,
    }),
  ),
}
```

**事件发布与订阅：**

```typescript
// 发布
Bus.publish(Session.Event.Created, { info: session })

// 订阅
const unsub = Bus.subscribe(Session.Event.Created, (event) => {
  console.log("New session:", event.properties.info)
})
```

**优点：**
- 模块间松耦合
- 支持多个监听者
- 类型安全的事件定义

### 4. 插件系统（Plugin System）

`src/plugin/` 允许通过钩子（hooks）扩展系统功能。

**钩子类型：**
- `auth` - 认证钩子
- `config` - 配置钩子
- `event` - 事件钩子
- `tool` - 工具钩子
- `chat` - 聊天钩子

**示例：**

```typescript
export interface Plugin {
  name: string
  hooks: {
    chat?: {
      system?: ChatHook
      params?: ChatHook
      headers?: ChatHook
    }
    // ... 其他钩子
  }
}
```

### 5. 工具注册表（Tool Registry）

`src/tool/registry.ts` 实现了动态工具发现和注册。

**工具定义模式：**

```typescript
export const MyTool = Tool.define("my_tool", {
  description: "Tool description",
  parameters: z.object({
    input: z.string().describe("Input parameter"),
  }),
  execute: async (args, ctx) => {
    return {
      title: "Result Title",
      output: "Result content",
      metadata: {},
    }
  },
})
```

**注册：**

```typescript
export async function all(): Promise<Tool.Info[]> {
  return [
    await ReadTool.init(),
    await EditTool.init(),
    await BashTool.init(),
    // ... 更多工具
  ]
}
```

### 6. 分层配置（Layered Configuration）

`src/config/config.ts` 实现了七层配置优先级系统。

**优先级从高到低：**
1. Remote `.well-known/opencode`
2. 全局配置 (`~/.config/opencode/config.json`)
3. 自定义配置 (`OPENCODE_CONFIG` 环境变量)
4. 项目配置 (`.opencode/config.json`)
5. `.opencode` 目录（父目录）
6. 内联配置（文档内）
7. 托管配置（企业）

## 数据流向

### 用户请求处理流程

```
用户输入
   ↓
CLI 命令解析 (Yargs)
   ↓
中间件处理 (日志、环境变量)
   ↓
项目上下文初始化 (Instance.provide)
   ↓
会话创建/获取
   ↓
消息构建 (MessageV2)
   ↓
LLM 流式调用 (LLM.stream)
   ↓
工具执行 (Tool.execute)
   ↓
结果处理与存储 (Storage)
   ↓
事件发布 (Bus)
   ↓
用户界面更新
```

### 流式响应事件流

```
LLM.stream()
   ↓
┌─────────────────────────────────────────────────────────────┐
│  事件类型流转：                                               │
│                                                             │
│  start →                                                   │
│  reasoning-start → reasoning-delta → reasoning-end →       │
│  text-start → text-delta → text-end →                      │
│  tool-input-start → tool-call → tool-result/error →        │
│  start-step → finish-step →                                 │
│  finish                                                     │
└─────────────────────────────────────────────────────────────┘
   ↓
SessionProcessor 处理
   ↓
存储到 Storage
   ↓
发布到 Bus
   ↓
SSE 推送到客户端
```

## 关键技术栈

- **运行时**: Bun
- **语言**: TypeScript
- **CLI 框架**: Yargs
- **HTTP 框架**: Hono
- **AI SDK**: Vercel AI SDK (`ai` 包)
- **校验**: Zod
- **工具库**: Remeda
- **持久化**: 文件系统（通过 Storage 抽象）
- **事件**: 发布订阅模式（自定义 Bus）
- **测试**: Bun test
