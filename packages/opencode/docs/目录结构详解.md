# OpenCode 目录结构详解

## 概述

OpenCode 采用清晰的模块化目录结构，每个目录负责特定的功能领域。这种设计便于代码维护、功能扩展和团队协作。

## 根目录结构

```
src/
├── acp/           # Agent Client Protocol 实现
├── agent/         # AI 代理系统
├── auth/          # 身份认证
├── cli/           # 命令行界面
├── command/       # 命令定义
├── config/        # 配置管理
├── env/           # 环境变量
├── file/          # 文件系统操作
├── format/        # 格式化工具
├── global/        # 全局变量和常量
├── id/            # 唯一标识生成
├── installation/  # 安装相关
├── lsp/           # Language Server Protocol
├── mcp/           # Model Context Protocol
├── permission/    # 权限管理
├── plugin/        # 插件系统
├── project/       # 项目管理
├── provider/      # AI 提供商
├── scheduler/     # 调度器
├── server/        # 服务器实现
├── session/       # 会话管理
├── share/         # 分享功能
├── skill/         # 技能系统
├── storage/       # 存储抽象
├── tool/          # 工具集成
├── util/          # 工具函数
└── worktree/      # 工作树管理
```

## 核心模块详解

### 1. acp/ - Agent Client Protocol

**功能**: 实现 Agent Client Protocol，用于代理间通信。

**核心文件**:

- `session.ts` - ACP 会话管理
- `types.ts` - ACP 类型定义
- `agent.ts` - ACP 代理实现
- `README.md` - ACP 协议文档

**关键特性**:

- 标准化的代理通信协议
- 支持代理注册和发现
- 消息路由和转发
- 错误处理和重试

### 2. agent/ - AI 代理系统

**功能**: 管理和配置不同类型的 AI 代理。

**核心文件**:

- `agent.ts` - 代理核心实现
- `generate.txt` - 代码生成提示模板
- `prompt/` - 各种场景的提示模板
- `compaction.txt`, `explore.txt`, `summary.txt`, `title.txt` - 专用提示

**关键特性**:

- 多种代理模式 (subagent, primary, all)
- 动态代理加载
- 代理协作机制
- 权限和行为控制

### 3. cli/ - 命令行界面

**功能**: 提供丰富的命令行工具和用户交互。

**核心文件**:

- `bootstrap.ts` - 项目初始化
- `ui.ts` - 用户界面组件
- `logo.ts` - Logo 显示
- `cmd/` - 各种命令实现
  - `run.ts` - 运行命令
  - `auth.ts` - 认证命令
  - `agent.ts` - 代理管理命令
  - `serve.ts` - 服务器命令
  - `tui/` - 终端界面命令

**关键特性**:

- 基于 Yargs 的命令框架
- 彩色输出和样式系统
- 进度显示和交互提示
- 错误处理和帮助系统

### 4. tool/ - 工具集成

**功能**: 提供标准化的工具集成框架。

**核心文件**:

- `tool.ts` - 工具核心接口
- `registry.ts` - 工具注册表
- 各种工具实现:
  - `read.ts`, `write.ts`, `edit.ts` - 文件操作
  - `bash.ts` - 命令执行
  - `grep.ts`, `glob.ts` - 搜索工具
  - `websearch.ts`, `webfetch.ts` - 网络工具
  - `task.ts`, `todo.ts` - 任务管理
  - `lsp.ts` - LSP 集成

**关键特性**:

- 统一的工具接口
- 参数验证和错误处理
- 权限控制和安全机制
- 插件工具支持

### 5. session/ - 会话管理

**功能**: 管理用户与 AI 的交互会话。

**核心文件**:

- `index.ts` - 会话核心逻辑
- `llm.ts` - LLM 流式处理
- `message.ts`, `message-v2.ts` - 消息系统
- `prompt.ts` - 系统提示
- `processor.ts` - 消息处理
- `prompt/` - 各种提示模板

**关键特性**:

- 会话状态管理
- 流式响应处理
- 消息历史和压缩
- 权限集成

### 6. provider/ - AI 提供商

**功能**: 集成和管理多个 AI 服务提供商。

**核心文件**:

- `provider.ts` - 提供商核心
- `transform.ts` - 模型参数转换
- `models.ts` - 模型管理
- 各种提供商实现

**关键特性**:

- 多提供商统一接口
- 动态提供商发现
- 认证和配置管理
- 成本和使用跟踪

### 7. project/ - 项目管理

**功能**: 管理代码项目和工作空间。

**核心文件**:

- `project.ts` - 项目核心
- `instance.ts` - 项目实例
- `bootstrap.ts` - 项目初始化
- `vcs.ts` - 版本控制集成
- `state.ts` - 项目状态

**关键特性**:

- 项目元数据管理
- 工作树支持
- VCS 集成 (Git)
- 项目生命周期管理

### 8. config/ - 配置管理

**功能**: 管理系统配置和用户设置。

**核心文件**:

- `config.ts` - 配置核心
- `markdown.ts` - Markdown 配置

**关键特性**:

- 分层配置系统
- 动态配置更新
- 配置验证
- 默认值管理

### 9. storage/ - 存储抽象

**功能**: 提供统一的存储抽象层。

**核心文件**:

- `storage.ts` - 存储核心

**关键特性**:

- 多存储后端支持
- 数据持久化
- 缓存机制
- 数据迁移

### 10. plugin/ - 插件系统

**功能**: 支持功能扩展和第三方集成。

**关键特性**:

- 插件发现和加载
- 标准化插件接口
- 生命周期管理
- 依赖解析

## 设计模式

### 依赖注入

使用 `Instance.provide()` 和 `Context` 系统实现依赖注入。

### 事件驱动

通过 `Bus` 和 `BusEvent` 实现事件驱动的架构。

### 状态管理

每个模块都有自己的状态管理机制，支持持久化和缓存。

### 插件化

核心系统支持插件扩展，保持系统的可扩展性。

## 最佳实践

### 模块独立性

每个模块都有明确的职责边界，减少模块间的耦合。

### 接口标准化

使用 TypeScript 接口定义标准化的模块交互。

### 配置驱动

通过配置文件控制功能启用和行为调整。

### 错误处理

每个模块都有完善的错误处理和日志记录机制。

这种模块化设计使得 OpenCode 具有良好的可维护性、可扩展性和可测试性，同时也便于新功能的开发和集成。
